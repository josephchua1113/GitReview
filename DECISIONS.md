# git_history.py: decisions the spec didn't cover

1. **Parsing.** `git log` runs with `-z` and NUL-separated fields. A NUL byte can't appear in a commit message, name, email or date, and `-z` stops git from quoting unusual paths (tabs, newlines, non-ASCII characters). The command also adds `--encoding=UTF-8 --no-color --no-show-signature --no-mailmap`, so user git config can't change the output. Output that doesn't parse becomes an error for that repository. Nothing is dropped silently.
2. **Remote-only refs.** Branches are listed with `%(refname)` instead of `%(refname:short)`. The short form turns into `remotes/origin/...` when a local branch has the same name, and that would silently hide the remote branch. `git log` also uses full `refs/remotes/...` names, so a local branch or tag with the same name is never read.
3. **Versions.** Trailing `.0` parts don't change a version: `19.17` equals `19.17.0`. Two such branches are a tie, and the tie is reported as an error. Country is ASCII letters only and is case-sensitive. Version is ASCII digits and dots.
4. **Error vs. No change.** Fetch failure, no lower branch, a tie and parse or git failures go in the red **Errors** group at the top. A missing target branch and an empty `base..target` go in the **No change** group. Within each group, repositories are sorted alphabetically, ignoring case. Files are sorted the same way.
5. **Renames and copies** are listed under the new path. The entry shows `old → new` and the score, for example `R087`. Searching the old path also finds the entry.
6. **Author email** (`%ae`) is shown next to the name and is searchable. It is left out when it is empty.
7. **Commit messages.** Only the trailing newline that git adds is removed. Everything else is shown unchanged.
8. **DIFF_URL_TEMPLATE** is `{"commit": ..., "compare": ...}` (a 2-tuple also works). It is checked at startup: only known placeholders are allowed, and it must start with `{base_url}` or `http(s)://`. `{path_sha1}` was added for self-hosted GitLab anchors. The template is used only for hosts that aren't recognised. Branch names are encoded with `/` as `%2F`. Paths keep `/`.
9. **Remote URLs.** Credentials in https URLs are removed, and ssh ports are dropped. Azure's `git@ssh.dev.azure.com:v3/org/proj/repo` becomes `https://dev.azure.com/org/proj/_git/repo`. Older `*.visualstudio.com` Azure URLs aren't recognised and need the template. Local paths and `file://` remotes give no links.
10. **Links not narrowed to the file.** Azure DevOps commit and compare links open the whole commit or compare page, because no file parameter or anchor could be confirmed. Bitbucket's `source%0Ddestination` order and its `#chg-<path>` anchor come from Bitbucket's UI behaviour, not from written documentation. Check one generated Bitbucket link before relying on it.
11. **Filters and print.** Search and the status filter hide only individual entries. Error and No change repositories are never hidden. A banner says when a filter is active, and a repository whose entries are all filtered out shows a "no entries match" line. Printing expands every section and ignores filters, so the printout is always complete. Merge commits without files have their own status checkbox, "Commits with no file changes".
12. **Inputs and environment.** `REMOTE_NAME` may not contain `/`, because the `<remote>/` prefix must be unambiguous. git runs with `GIT_TERMINAL_PROMPT=0`, so a fetch never waits for a password, and inherited `GIT_DIR` and `GIT_WORK_TREE` are removed. There is no fetch timeout.
